# 1. Library Identity and Status

Research snapshot: 2026-09-04. Ghostty `main` resolved to commit [`492300cad104195411d12217dd22f1cd05f31376`](https://github.com/ghostty-org/ghostty/commit/492300cad104195411d12217dd22f1cd05f31376); commit-pinned links below make “HEAD” reproducible.

| Name | What exists | PTY + renderer? | Status |
|---|---|---:|---|
| `libghostty` | The project/umbrella name for reusable Ghostty components; the 1.3.0 notes also call the extracted, full-featured **Zig module** `libghostty`. It is not the name of a released, stable, full-terminal C library. ([HEAD README](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/README.md#roadmap-and-status), [1.3.0 notes](https://ghostty.org/docs/install/release-notes/1-3-0#libghostty)) | Not as a supported public C surface | The Zig module is described as full-featured, but no versioned library release has been tagged and the public C ABI remains pre-release. ([1.3.0 notes](https://ghostty.org/docs/install/release-notes/1-3-0#libghostty)) |
| `libghostty-internal` / `include/ghostty.h` | Renderer-bearing embedder interface used by Ghostty.app. The header calls itself “Ghostty’s internal embedder API,” says its only consumer is the macOS app, and directs external embedders elsewhere. It exposes `ghostty_app_t`, `ghostty_surface_t`, configuration/runtime callbacks and macOS/Metal functions. ([`ghostty.h`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty.h#L1-L11)) | **Yes**: a surface owns terminal-process/PTY behavior and rendering; on macOS it attaches to an `NSView` and uses Metal. ([surface API](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty.h)) | Explicitly internal, partly undocumented, and not designed for external use. The output is `libghostty-internal.a`; `build.zig` says the historical “libghostty” name is misleading GUI glue. ([`GhosttyLib.zig`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/src/build/GhosttyLib.zig#L21-L80), [`build.zig`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/build.zig#L212-L239)) |
| `libghostty-vt` | The supported external C component: VT parsing/state with screen, cursor, styles, scrollback/reflow, input encoding, selection/search/snapshots and optional Kitty graphics state. The umbrella header is `include/ghostty/vt.h`, implementation root `src/lib_vt.zig`, and Unix link names `libghostty-vt.*`. ([`vt.h`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt.h#L1-L49), [`lib_vt.zig`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/src/lib_vt.zig), [`GhosttyLibVt.zig`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/src/build/GhosttyLibVt.zig)) | **No**: it opens no PTY and contains no Ghostty GPU/text renderer. The embedder owns I/O and paints `GhosttyRenderState`; effects such as PTY write-back arrive through callbacks. ([terminal effects](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/terminal.h), [render state](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/render.h)) | Terminal behavior is mature, but the C API is explicitly “incomplete,” WIP and expected to break. The announcement called the core heavily tested while the API was alpha/early-testing quality. ([`vt.h`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt.h#L4-L26), [announcement](https://mitchellh.com/writing/libghostty-is-coming#libghostty-vt-status)) |
| `ghostty-vt` | An artifact/target/module stem, not a different library: Zig calls the shared target `ghostty-vt`, CMake exports that target, and the XCFramework is `ghostty-vt.xcframework`; installed Unix libraries gain the conventional `lib` prefix. ([`GhosttyLibVt.zig`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/src/build/GhosttyLibVt.zig#L220-L237), [`CMakeLists.txt`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/CMakeLists.txt)) | Same as `libghostty-vt` | No separate `ghostty-vt` crate exists; the exact-name registry endpoint is 404. ([crates.io](https://crates.io/api/v1/crates/ghostty-vt)) |

Conclusion: **use `libghostty-vt` for the supported external boundary; treat `ghostty.h`/`libghostty-internal` as a private escape hatch; there is not yet a supported public full renderer+PTY C library named `libghostty`.** ([external-embedder direction](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty.h#L1-L11)) The announcement described a zero-dependency portable parser/state core and placed GPU rendering in later layers; HEAD has added input encoders and optional features but still no public renderer C API. ([announcement](https://mitchellh.com/writing/libghostty-is-coming#the-beginning-libghostty-vt), [`vt.h` groups](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt.h#L28-L49))

# 3. Build Path (macOS)

At researched HEAD, `build.zig.zon` requires Zig **0.16.0** and `build.zig` enforces it. ([`build.zig.zon`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/build.zig.zon), [`build.zig`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/build.zig#L6-L16)) Ghostty’s web build page still lists tip as 0.15.2 and warns only the exact compiler is supported; it is stale relative to commit-pinned HEAD, so use 0.16.0 here. Stable 1.3.x uses 0.15.2. ([build docs](https://ghostty.org/docs/install/build#zig-version)) Git, Xcode/Command Line Tools and the macOS SDK are also needed; XCFramework creation invokes `xcodebuild`. ([macOS prerequisites](https://ghostty.org/docs/install/build#macos), [`Config.zig`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/src/build/Config.zig#L537-L556))

Cargo-friendly native build:

```sh
zig build \
  -Demit-lib-vt=true \
  -Dapp-runtime=none \
  -Demit-xcframework=false \
  -Doptimize=ReleaseFast \
  -Dcpu=baseline \
  --prefix "$LIBGHOSTTY_VT_PREFIX"
```

The current option is `-Demit-lib-vt`, not `-Demit-lib`; it sets lib-vt-only defaults. `-Dapp-runtime=none` is explicit but redundant in lib-vt mode. Without `-Demit-lib-vt`, runtime `none` selects private GUI-core outputs, which `build.zig` says are not public libghostty. ([`Config.zig`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/src/build/Config.zig#L81-L88), [`build.zig`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/build.zig#L212-L239), [`AGENTS.md`](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/AGENTS.md)) On a native Mac with `xcodebuild`, lib-vt mode defaults XCFramework emission true; omit the false override or pass true when it is wanted. ([default](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/src/build/Config.zig#L537-L556), [Apple build](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/src/build/GhosttyLibVt.zig#L124-L218))

# 4. Integration Architecture Options

## 4a. Private full Ghostty surface in a child `NSView`

The demonstrated route is: obtain GPUI’s AppKit raw handle, create an `NSView` child, pass it as `ghostty_surface_config_s.platform.macos.nsview`, call `ghostty_init`, `ghostty_config_new`, `ghostty_app_new` and `ghostty_surface_new`, forward input/focus/resize/visibility, and service `ghostty_app_tick`. Ghostty then owns the process/PTY and Metal renderer. ([internal header](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty.h), [`gpui-libghostty` shim](https://github.com/behzade/gpui-libghostty/blob/312d9ef810620ba22aaff6cd92fe741bb760bb34/crates/gpui-ghostty/shim/ghostty_surface.m#L99-L197))

GPUI exposes enough native plumbing to do this manually. `gpui::Window` implements `raw_window_handle::HasWindowHandle`; macOS returns `RawWindowHandle::AppKit(AppKitWindowHandle::new(native_view))`, the root `NSView`. ([GPUI `Window`](https://github.com/zed-industries/zed/blob/ee3b5558c581429633937e458fad8d109f29e9ee/crates/gpui/src/window.rs#L7098-L7110), [macOS implementation](https://github.com/zed-industries/zed/blob/ee3b5558c581429633937e458fad8d109f29e9ee/crates/gpui_macos/src/window.rs#L2205-L2212)) The alpha `gpui-libghostty` proves the pattern: it reads `handle.ns_view`, calls `[parent addSubview:view]`, then attaches the Ghostty surface. ([handle extraction](https://github.com/behzade/gpui-libghostty/blob/312d9ef810620ba22aaff6cd92fe741bb760bb34/crates/gpui-ghostty/src/terminal.rs#L440-L467), [child view](https://github.com/behzade/gpui-libghostty/blob/312d9ef810620ba22aaff6cd92fe741bb760bb34/crates/gpui-ghostty/shim/ghostty_surface.m#L99-L172))

GPUI does **not document a first-class arbitrary-`NSView` element** at this snapshot. Repository inspection found the raw root handle, not a supported child-view abstraction; `gpui-libghostty` manages frame/events itself and offers `Terminal::snapshot()` GPU readback when a normal GPUI overlay must replace the native surface. This is a workable bridge, not a stable GPUI hosting contract. ([GPUI raw handle](https://github.com/zed-industries/zed/blob/ee3b5558c581429633937e458fad8d109f29e9ee/crates/gpui/src/window.rs#L7098-L7110), [snapshot guidance](https://github.com/behzade/gpui-libghostty/blob/312d9ef810620ba22aaff6cd92fe741bb760bb34/README.md#terminal))

Risks: private symbols can change at any commit; native-child z-order, clipping, overlays, IME and accessibility sit outside GPUI’s scene; compilation is large; and the available integration labels itself alpha and pins Ghostty and GPUI revisions. ([private API warning](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty.h#L1-L11), [`gpui-libghostty` status/versioning](https://github.com/behzade/gpui-libghostty/blob/312d9ef810620ba22aaff6cd92fe741bb760bb34/README.md#status))

## 4b. Public `libghostty-vt`, application-owned PTY, GPUI renderer

1. Open a PTY and spawn the child. `portable-pty` exposes `native_pty_system().openpty(PtySize)` and slave `spawn_command`; lower-level `rustix-openpty::openpty(termios, winsize)` returns master/slave. ([`portable-pty`](https://docs.rs/portable-pty/latest/portable_pty/trait.PtySystem.html), [`rustix-openpty`](https://docs.rs/rustix-openpty/latest/rustix_openpty/fn.openpty.html)) `rustix` itself points to the separate `rustix-openpty` crate. ([`rustix::pty`](https://docs.rs/rustix/latest/rustix/pty/index.html))
2. Create `GhosttyTerminal`, install `GHOSTTY_TERMINAL_OPT_WRITE_PTY` and other effect callbacks, feed PTY output to `ghostty_terminal_vt_write`, and write `GhosttyTerminalWritePtyFn` bytes back to the PTY so query replies work. Callbacks run synchronously and may not re-enter the same terminal. ([effects contract](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/terminal.h#L65-L110))
3. On resize, resize the OS PTY and call `ghostty_terminal_resize(columns, rows, cell_width_px, cell_height_px)`. Update `GhosttyRenderState`, iterate dirty rows/cells, resolve styles/graphemes/colors, and paint backgrounds, cursor, selection and shaped glyph runs with GPUI. ([terminal API](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/terminal.h), [render API](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/render.h), [cell API](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/screen.h))
4. Convert GPUI events through `ghostty_key_encoder_*`, `ghostty_mouse_encoder_*`, `ghostty_focus_encode` and `ghostty_paste_encode`, then send encoded bytes to the PTY. ([key](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/key/encoder.h), [mouse](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/mouse/encoder.h), [focus](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/focus.h), [paste](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/paste.h))

This is the intended external API and produces a normal GPUI element, so clipping, overlays, scrollbars and theme integration remain coherent. Cost: font fallback/shaping, wide and combining graphemes, ligatures, underline variants, cursor/selection, damage, DPI, hyperlinks, IME, accessibility and Kitty images are renderer work. The headers expose data, not GPUI drawing code. ([render](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/render.h), [Kitty graphics](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/kitty_graphics.h), [scope](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt.h#L15-L49))

## 4c. Alternatives

`alacritty_terminal` is the low-risk GPUI fit. crates.io latest is 0.26.0 (2026-04-06, MSRV 1.85); Zed currently pins a forked Git revision and directly uses it. ([crates.io](https://crates.io/api/v1/crates/alacritty_terminal), [Zed dependencies](https://github.com/zed-industries/zed/blob/ee3b5558c581429633937e458fad8d109f29e9ee/Cargo.toml), [Zed terminal](https://github.com/zed-industries/zed/blob/ee3b5558c581429633937e458fad8d109f29e9ee/crates/terminal/src/terminal.rs)) Reusing Zed patterns minimizes GPUI risk, but loses exact Ghostty behavior and may require tracking Zed’s fork. - Every `*.a`: **NOT FOUND anywhere under `/Applications/Ghostty.app`**. Source builds install `libghostty-vt.a` into their chosen prefix; the cask exposes no such prefix. ([static install](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/build.zig#L159-L189), [cask artifacts](https://formulae.brew.sh/api/cask/ghostty.json))

Thus the installed app is not an SDK and cannot be linked in place. Obtain the commit-matched tip XCFramework or build lib-vt from source; do not scrape private symbols from the executable. ([tip release](https://github.com/ghostty-org/ghostty/releases/tag/tip), [external-embedder guidance](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty.h#L1-L11))

# 8. RECOMMENDATION (clear pick among 4a/4b/4c with rationale)

**Pick 4b: public `libghostty-vt` + `portable-pty` + a GPUI-native renderer, pinned at a known Ghostty commit.** It is the only choice that both uses Ghostty’s engine and follows Ghostty’s external-embedder contract. It also keeps the terminal in GPUI’s rendering/compositing model rather than placing a private native child surface beside it. ([external guidance](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty.h#L1-L11), [lib-vt scope](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt.h), [`portable-pty`](https://docs.rs/portable-pty/latest/portable_pty/))

Treat it as a **commit-pinned pre-1.0 dependency**, hide it behind a small Rust module/trait, and generate bindings from precisely the headers used to build the archive. The main schedule risk is renderer effort, not PTY/parser work; explicitly scope shaping/fallback, damage, selection/cursor, IME/accessibility and Kitty images. ([instability warning](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt.h#L10-L26), [render API](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/render.h), [Kitty API](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt/kitty_graphics.h))

Reject 4a for production unless the product explicitly accepts a private ABI fork. It is viable for prototyping and `gpui-libghostty` accelerates evaluation, but Ghostty labels the interface internal and the integration labels itself alpha. It also needs Rust 1.95 while this host has 1.94.1. ([private warning](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty.h#L1-L11), [`gpui-libghostty`](https://github.com/behzade/gpui-libghostty/blob/312d9ef810620ba22aaff6cd92fe741bb760bb34/README.md))

Keep 4c/`alacritty_terminal` as the schedule fallback. If a polished GPUI terminal soon matters more than Ghostty semantics, it is rational because Zed already exercises that architecture. `wezterm-term` is capable but has neither a crates.io release nor demonstrated GPUI path. ([Zed terminal](https://github.com/zed-industries/zed/blob/ee3b5558c581429633937e458fad8d109f29e9ee/crates/terminal/src/terminal.rs), [`alacritty_terminal`](https://crates.io/api/v1/crates/alacritty_terminal), [`wezterm-term`](https://github.com/wezterm/wezterm/blob/d4f5c4878a7f72b3fa53ff963a1fea790810d31a/term/README.md))

# 9. Proposed build.rs Strategy Sketch for the recommended option

Use a small sys crate such as `ghostty-vt-head-sys` whose three inputs are one lockstep unit: Ghostty commit `492300…`, copied `include/ghostty/` headers from that commit, and Rust bindings generated from those headers. That prevents a newer dylib from satisfying the link while violating pre-1.0 layouts. ([`vt.h` warning](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/include/ghostty/vt.h#L10-L26), [wrapper warning](https://github.com/Uzaaft/libghostty-rs/blob/master/README.md#building))

Resolution order:

1. If `LIBGHOSTTY_VT_PREFIX` is set, validate `include/ghostty/vt.h`, `lib/libghostty-vt.a`, and a commit/ABI stamp, then link it. This supports CI-prebuilt, network-free builds. ([Ghostty installed outputs](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/src/build/GhosttyLibVt.zig), [wrapper external-source/pkg-config pattern](https://github.com/Uzaaft/libghostty-rs/blob/master/README.md#building))
2. Otherwise use a vendored/submodule checkout pinned to `492300…`; never clone floating `main` in `build.rs`. Use `ZIG` or `zig`, run `zig version`, and require 0.16.0. ([Ghostty pin](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/build.zig.zon), [wrapper pattern](https://github.com/Uzaaft/libghostty-rs/blob/master/crates/libghostty-vt-sys/build.rs))
3. Put `ZIG_LOCAL_CACHE_DIR`, `ZIG_GLOBAL_CACHE_DIR` and the install prefix below `OUT_DIR`; optionally accept `GHOSTTY_ZIG_SYSTEM_DIR` for prefetched offline dependencies. ([wrapper README](https://github.com/Uzaaft/libghostty-rs/blob/master/README.md#building), [build.rs](https://github.com/Uzaaft/libghostty-rs/blob/master/crates/libghostty-vt-sys/build.rs))
4. Execute section 3’s command with `-Demit-xcframework=false`, verify the archive, emit `cargo:rustc-link-search=native=…` and `cargo:rustc-link-lib=static=ghostty-vt`; parse `libghostty-vt-static.pc` when system integration is enabled. ([artifacts](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/build.zig#L127-L189), [pkg-config](https://github.com/ghostty-org/ghostty/blob/492300cad104195411d12217dd22f1cd05f31376/src/build/GhosttyLibVt.zig#L510-L575))
5. Generate bindings during maintainership/CI and check them in, avoiding a libclang requirement for every user. If bindgen runs in `build.rs`, target only matched `include/ghostty/vt.h` and require Xcode CLT. Existing sys crates demonstrate checked-in and build-time variants. ([Uzaaft manifest](https://github.com/Uzaaft/libghostty-rs/blob/master/crates/libghostty-vt-sys/Cargo.toml), [mnml README](https://github.com/chris-mclennan/mnml/blob/main/crates/mnml-libghostty-vt-sys/README.md))

Illustrative core (error handling/target mapping abbreviated):

```rust
use std::{env, path::PathBuf, process::Command};

const GHOSTTY_COMMIT: &str = "492300cad104195411d12217dd22f1cd05f31376";
const REQUIRED_ZIG: &str = "0.16.0";

fn main() {
    println!("cargo:rerun-if-env-changed=LIBGHOSTTY_VT_PREFIX");
    println!("cargo:rerun-if-env-changed=GHOSTTY_SOURCE_DIR");
    println!("cargo:rerun-if-env-changed=ZIG");

    let out = PathBuf::from(env::var_os("OUT_DIR").unwrap());
    let prefix = env::var_os("LIBGHOSTTY_VT_PREFIX")
        .map(PathBuf::from)
        .unwrap_or_else(|| out.join("ghostty-vt-prefix"));

    if env::var_os("LIBGHOSTTY_VT_PREFIX").is_none() {
        let source = PathBuf::from(env::var_os("GHOSTTY_SOURCE_DIR")
            .expect("provide checkout pinned to GHOSTTY_COMMIT"));
        // Validate a checked-in commit stamp equals GHOSTTY_COMMIT here.
        let zig = env::var_os("ZIG").unwrap_or_else(|| "zig".into());
        let version = Command::new(&zig).arg("version").output().unwrap();
        assert_eq!(String::from_utf8_lossy(&version.stdout).trim(), REQUIRED_ZIG);

        let status = Command::new(&zig)
            .current_dir(&source)
            .args([
                "build", "-Demit-lib-vt=true", "-Dapp-runtime=none",
                "-Demit-xcframework=false", "-Doptimize=ReleaseFast",
                "-Dcpu=baseline", "--prefix",
            ])
            .arg(&prefix)
            .env("ZIG_LOCAL_CACHE_DIR", out.join("zig-local-cache"))
            .env("ZIG_GLOBAL_CACHE_DIR", out.join("zig-global-cache"))
            .status().unwrap();
        assert!(status.success());
    }

    assert!(prefix.join("lib/libghostty-vt.a").is_file());
    assert!(prefix.join("include/ghostty/vt.h").is_file());
    println!("cargo:rustc-link-search=native={}", prefix.join("lib").display());
    println!("cargo:rustc-link-lib=static=ghostty-vt");
}
```
